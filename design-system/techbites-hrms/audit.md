# TechBites HRMS — UI/UX Audit

**Date:** 2026-09-18 · **Baseline commit:** `d885c19` · **Scope:** Dashboard, Employees, Attendance, Leave Requests, Payroll, Settings, plus the shared shell (Sidebar, TopNav, modals)
**Method:** ui-ux-pro-max v2.13.0 priority rules (`references/quick-reference.md`), reading the code only. The app was not run in a browser. Contrast ratios were computed with the WCAG 2.x formula from Tailwind v4 `oklch` tokens in `node_modules/tailwindcss/theme.css`.
**Stack:** Next.js 16.3.5 (App Router), React 19.2, Tailwind CSS v4, lucide-react, clsx + tailwind-merge. No component library (no shadcn/Radix).
**Brand kept:** indigo-600 primary (`#4f39f6`; white text on it = 6.44:1, passes), slate-900 navy sidebar, the new logo. The only color changes proposed below are for pairs that fail contrast.

**Legend:**
- **Priority:** P1 = Critical (Accessibility, and broken or misleading behavior) · P2 = High (Layout, Navigation, and the issues you reported) · P3 = Medium (Forms & Feedback, Typography) · P4 = Low (polish)
- **Effort:** S = under 1 hour · M = half a day to 1 day · L = more than 1 day
- **21st?** ✅ = a 21st component would fit · ➖ = use the existing code or a small local fix · ⚠️ = a 21st component fits, but it likely adds a Radix dependency, so check it against the "no second styling system" rule first

## Your four reported issues: verification

| # | Reported issue | Verdict | Evidence |
|---|---|---|---|
| U1 | Search placeholder contrast is too low | **Confirmed, and worse than reported** | The input sets no placeholder color, so Tailwind v4 preflight falls back to `currentColor` at 50% opacity, which gives `#888889` on `slate-50` = **3.37:1** (needs 4.5:1). | U4 | The floating round button at the bottom right overlaps the table | **Not found in the code** | No app code renders a fixed element other than the full-screen modal overlays. ## Design-system notes

- `MASTER.md` was generated with `"HR payroll admin dashboard enterprise"`, `--density 8 --variance 3 --motion 3`. The generator classified the project as "Smart Home/IoT Dashboard" and proposed a dark slate + green palette. **Neither was adopted.** A brand-lock note at the top of MASTER.md records this. The parts that still apply are the Swiss/minimal style, the dense spacing scale (8–32px) and subtle motion (200–250ms hover, reduced motion respected).
- Suggested semantic tokens, to add in `@theme` in `globals.css` when you implement:
  - `--color-primary`: indigo-600
  - `--color-text-muted`: slate-500
  - `--color-border-input`: slate-400 or darker. Input borders are **1.23:1** today (slate-200), which fails WCAG 1.4.11 non-text contrast (3:1). slate-400 is still only 2.63:1; slate-500 (4.77:1) passes.
  - `--color-success-fg`: emerald-700
  - `--color-warning-fg`: amber-700
  - `--color-danger-fg`: rose-700
- **Candidates for 21st** (marked ✅ / ⚠️ above; nothing searched or installed in this step): command palette (A2), KPI/stat card (L1), time-clock widget (L2), sidebar drawer (L3), dialog / alert-dialog (A4, F1), toast (F2). Anything Radix-based adds dependencies, so check it against the existing Tailwind-only conventions first.
